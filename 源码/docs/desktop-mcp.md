# 梦藏桌面 MCP

当前是 0.9.0 开发检查点。隔离验收通过，但正式应用资料库加载及 MCP 读取存在超时，已按用户要求暂停；本说明描述已实现的接口，不代表正式接入验收完成。见仓库中的「验收记录/桌面MCP-暂停检查点.md」。

梦藏 0.9.0 提供本机只读 MCP。它读取正在运行的桌面软件，不需要云端融合插件，不把整个资料库上传到云端，也没有 8 MiB 整库容量限制。

## 已提供的工具

| 工具 | 能力 |
| --- | --- |
| `library_status` | 两处资料来源的可用状态、条数及是否有遗漏 |
| `list_cards` | 分页列出已保存、未归档的资料 |
| `search_cards` | 检索完整已保存正文、注释、已有 OCR 和文档索引 |
| `read_card` | 按 Unicode 码点分页阅读正文、注释、OCR 或文档索引 |
| `read_image` | 返回 PNG/JPEG/GIF/WebP 本机图片的原生 MCP 图片内容 |
| `list_collections` | 收藏集及其有效资料引用 |
| `list_canvases` | 画布、有效节点和已有连线 |
| `read_document` | 阅读指定页已有文字索引和高亮，并报告缺页及部分索引 |

工具合并软件自身的 IndexedDB 已保存卡片与配置文件库中的材料、图书；同一实体的软件副本优先。隐藏或归档资料、未提交草稿、API 密钥及设置不提供给 MCP。资料文字只作为待引用内容，不作为指令执行。

## 连接方式

打开桌面梦藏。菜单「梦藏 → 本机 MCP 状态」显示接口是否就绪。普通 Node 运行安装包中独立的 stdio 文件：

```text
<Node 的绝对路径>
<梦藏.app>/Contents/Resources/app.asar.unpacked/mengcang-desktop-mcp.cjs
--desktop
<梦藏的 userData 绝对目录>
```

本机 Codex 使用名称 `mengcang-desktop` 注册此命令。更换安装版本后命令路径可以沿用；MCP 工具目录是否已刷新需要在 Codex 中实际验证。仅看到注册配置，不等于已成功读取资料。

stdio 程序通过当前用户私有的 Unix socket 请求软件读取资料。软件退出后会清理本进程连接；再次打开后客户端按最新连接继续读取。无需开放公网端口，MCP 不自动启动软件。

## 实际边界

- 图片原件单次响应最多 6 MiB，编码后适配 MCP SDK 的默认缓冲；这是单次传输限制，原件和整库容量不受此数值限制。较大的原图明确报错，不偷偷缩小或冒充读取。
- PDF/Word 首版读取已保存的文字索引；缺页或未索引时明确说明，没有重新解析原件。MCP 不生成 OCR、转录或向量索引。
- 远程网页或图片地址只返回来源信息，不自动下载；登录权限或网页内容采集需要相应独立能力。
- 本轮不提供新增、修改、删除资料的工具。
- MCP 本身不调用模型。Codex 进一步分析所取资料属于 Codex 对话的模型使用。
- 远端 dots 不会自动获得这台 Mac 的 stdio 进程。是否能调用本机接口需要单独验证，不能据本机接通而宣称远端接通。
- 卸载云端融合插件不会自动把它的资料复制到桌面库；原有云端资料和本地导入回执先保留，本轮没有迁移或删除它们。

## 验证

`npm test` 覆盖本机读取、权限与路径边界、原生 stdio、并发及退出清理。`verification/desktop-mcp-20261005/verify.mjs` 使用独立 Electron 软件目录、文件库和 IndexedDB，实际验证两个来源、超过 8 MiB 的正文库、原图字节、页索引和正常退出。测试不会读取正式资料，也不会发起模型请求。
