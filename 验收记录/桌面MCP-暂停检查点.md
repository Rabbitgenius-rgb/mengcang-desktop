# 桌面 MCP 暂停检查点

本次保存 0.9.0 开发源码及前次交付后的修复。用户要求暂停后续修复，先提交仓库。未创建新的安装包 Release，也未把尚未通过的正式验收标为完成。

## 已完成

- 增加 8 个本机只读 MCP 工具：资料库状态、卡片列表、全文关键词搜索、正文分页、原图读取、收藏集、画布、已有文档页索引。
- 合并软件已保存的 IndexedDB 卡片与本机文件库；排除草稿、隐藏及归档卡片、设置和凭据。
- 使用当前用户私有 Unix socket 和独立 stdio 入口；正常退出会清理本进程连接。
- 单图响应支持 PNG/JPEG/GIF/WebP，原图字节上限 6 MiB；这是单次传输上限，整库没有 8 MiB 容量限制。
- 后端回归 280 项通过；图片传输上限调整后的相关检查 30 项通过。
- 隔离 Electron 验收：103 条资料、8 个工具、11 项检查通过，包含超过 8 MiB 的正文库、两处图片来源、文档缺页说明及退出清理。没有模型调用。
- 0.9.0 候选构建、打包、签名验证通过；已备份旧程序并在本机更新、重开。
- Codex 已登记 `mengcang-desktop` 的 stdio 配置；软件菜单显示 MCP 就绪。

## 尚未通过

- 正式应用重开后仍停在“正在打开梦藏资料库”。实际 `library_status` 在 30 秒后超时，尚未成功验收正式正文或图片读取。
- 直接读取同一本机文件库未见异常，不能据此确定正式应用超时根因。
- 当前 Codex 聊天尚未发现并调用新增工具；配置登记及独立 stdio 初始化不能替代宿主接入验收。
- PDF/Word 仅读取已有文字索引；未索引页面明确报告缺失，不重新解析原件。远程图片不自动下载。
- 远端 dots 调用这台 Mac 的本机接口尚未验证。

## 恢复工作的位置

先定位正式应用的资料加载及读取超时，再检查正式文字、图片、重开与退出行为，最后验证 Codex 宿主发现并调用工具。失败时可回滚到保留的旧应用；不清空用户目录或原资料库。

仓库只保存源码、测试和本记录。本机 API 设置、用户资料、MCP 连接令牌、应用备份及原始诊断日志未上传。
